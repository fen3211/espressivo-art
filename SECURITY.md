# Порядок обеспечения безопасности и Threat Model платформы espressivo ART

## 1. Политика безопасности (Security Policy)

Платформа **espressivo ART** обрабатывает персональные данные несовершеннолетних участников, платёжные транзакции оргвзносов и финансовый учёт комиссий наставников. Безопасность системы спроектирована по стандартам **OWASP ASVS 4.0 (Level 2)**, **OWASP Top 10** и требованиям законодательства РФ (**152-ФЗ**, **149-ФЗ**).

---

## 2. Ключевые архитектурные барьеры безопасности

### 2.1. Платёжная безопасность (Payment Gateway & Webhook Security)
- **Безусловный запрет Mock-эквайринга в Production**:
  При `NODE_ENV === "production"` методы `MockPaymentGateway` безусловно возвращают отказ. Никакие переменные окружения (`ENABLE_MOCK_CHECKOUT`) не могут отменить этот запрет на боевом контуре.
- **Канонический HMAC-SHA256 с валютой**:
  Подпись вебхука формируется по строгому каноническому шаблону: `${transactionId}:${amount}:${currency}:${status}` с константным сравнением буферов (`crypto.timingSafeEqual`) для защиты от Timing Attacks.
- **Строгая идемпотентность (Atomic CAS)**:
  Параллельные вебхуки обрабатываются через атомарную операцию Compare-And-Swap:
  ```typescript
  await tx.paymentTransaction.updateMany({
    where: { id: txId, status: { not: "CONFIRMED" } },
    data: { status: "CONFIRMED" }
  });
  ```
  Это гарантирует, что даже при одновременном поступлении нескольких одинаковых вебхуков начисление 20% комиссии наставнику происходит **строго один раз**.

### 2.2. Аутентификация, Rate Limiting и защита от перебора
- **Безусловная блокировка демонстрационных аккаунтов в Production**:
  Служебные аккаунты (`*@espressivo.art`) безусловно заблокированы в `NODE_ENV === "production"`. Для предотвращения утечки существования учетных записей (User Enumeration) и атак по времени сервер выполняет фиктивный расчёт bcrypt (`DUMMY_BCRYPT_HASH`) и возвращает стандартный `401 INVALID_CREDENTIALS`.
- **Единая архитектура Rate Limiting (`lib/rate-limiter.ts`)**:
  - Поддержка распределённых хранилищ: **Upstash Redis** (Serverless REST API) и **Generic Redis** (TCP).
  - **Fail-Closed в Production**: при отсутствии подключенного распределённого хранилища в production сервер возвращает `HTTP 503 SERVICE_UNAVAILABLE`, не допуская создания ложного ощущения защищённости на нескольких инстансах.
  - **Защита от спуфинга IP**: клиентский заголовок `X-Forwarded-For` не принимается на веру без учёта числа доверенных хопов (`TRUSTED_PROXY_COUNT`), либо извлекается верифицированный заголовок реверс-прокси (`CF-Connecting-IP`, `X-Real-IP`).

### 2.3. Серверная изоляция слепого судейства (Blind Audition Enforced)
- Для роли `JURY` сервер **никогда** не передаёт `videoUrl` в API-ответах (`videoUrl: null`).
- Эксперт жюри получает исключительно защищенный аудиоэндпоинт `/api/jury/applications/[id]/audio` с обязательной проверкой назначения на заявку (`juryUserId === session.userId`).
- Клиентский интерфейс блокирует переключение слепого режима (`allowToggleBlindMode={false}`). В DOM монтируется исключительно аудиоэлемент, что исключает извлечение видеокадров через DevTools.
- Администраторам доступен авторизованный просмотр видеозаписи для модерации.

### 2.4. Защита персональных данных несовершеннолетних (152-ФЗ ст. 10.1)
- По умолчанию в публичном реестре проверки подлинности дипломов (`/api/public/verify-certificate/[token]`) отображаются **только** подтверждение аутентичности, номер диплома, конкурс, номинация и наградная квалификация.
- ФИО конкурсанта и конкурсный балл (`totalScore`) **не раскрываются**, если законный представитель не предоставил отдельного добровольного согласия на распространение персональных данных (`consentPublicStream: true`).
- Поиск дипломов по порядковым номерам запрещен: верификация выполняется исключительно по криптографическому токену с энтропией 256 бит.

## 3. Матрица угроз (Threat Model & Mitigations)

| Вектор атаки (Threat) | Категория | Механизм защиты платформы | Статус |
|---|---|---|---|
| Подделка вебхука эквайринга | Tampering / Spoofing | Обязательная валюта в HMAC-SHA256, сверка с БД, `timingSafeEqual` | **MITIGATED** |
| Повторный вебхук / Race condition | Replay / Race condition | Атомарный CAS `updateMany` со статусом `not: CONFIRMED` | **MITIGATED** |
| Подбор паролей / Brute-force | Broken Authentication | Распределённый Rate Limiter (5 попыток/10 мин), Fail-Closed | **MITIGATED** |
| Обход лимитов через `X-Forwarded-For` | IP Spoofing | Выбор правого хопа доверенного прокси, `CF-Connecting-IP` | **MITIGATED** |
| User Enumeration на `/api/auth/login` | Information Disclosure | `DUMMY_BCRYPT_HASH`, константное время, унифицированный 401 | **MITIGATED** |
| Подглядывание жюри за участником | Privilege Escalation | Серверное обнуление `videoUrl`, выделенный `/audio` роут | **MITIGATED** |
| Просмотр чужих заявок (IDOR) | Broken Object Authorization | Проверка владения на уровне запросов Prisma к БД | **MITIGATED** |
| Утечка ПДн детей через верификацию | Privacy Violation (152-ФЗ) | Сокрытие имени и баллов по умолчанию без согласия ст. 10.1 | **MITIGATED** |
| Использование mock-платежей в проде | Security Bypass | Безусловный отказ в `NODE_ENV === "production"` | **MITIGATED** |

## 4. Сообщение об уязвимостях (Vulnerability Disclosure)

Если вы обнаружили потенциальную уязвимость в платформе espressivo ART:
1. Пожалуйста, не публикуйте информацию об уязвимости публично в GitHub Issues.
2. Направьте подробный отчёт службе безопасности по адресу: **security@espressivo.art**.
3. Укажите шаги для воспроизведения, предполагаемый вектор атаки и оценку критичности.
4. Служба безопасности обязуется подтвердить получение отчёта в течение 24 часов и выпустить исправление в приоритетном порядке.
