# espressivo ART — Project Execution Plan

## 1. Обзор проекта
Платформа международных творческих конкурсов **espressivo ART**.
Флагманский конкурс: **espressivo VOCAL — Young Talents** (дети и молодежь).

## 2. Ключевые архитектурные и бизнес-принципы
1. **Строгое разделение дизайна**:
   - **Публичный сайт**: Стиль *Art+Commerce* (Quiet Editorial Gallery), монохромная эстетика костяной бумаги (`#000000`, `#e7e7e7`, `#121212`), Adobe Garamond 400 + Akzidenz Grotesk uppercase, 0px border-radius, полноформатная арт-фотография.
   - **Кабинеты (Dashboards)**: Стиль *Frame.io* (Midnight Cinema Projection Room), глубокий космос (`#0a0a13`, `#040407`, `#08080c`, `#fcfcfc`), акцент Iris Glow (`#6199f6`), фиолетовые полупрозрачные границы Twilight (`#4f4f80`), 10px радиус карточек, 100px пилюли, кинематографичный профессиональный интерфейс.
2. **Безопасность несовершеннолетних**:
   - Закрытые видеоматериалы (доступ только для жюри и администратора).
   - Анонимизация участников для жюри (жюри видит ID заявки, категорию, репертуар, видео, но не видит полных личных контактов ребенка).
   - Строгая фиксация согласий законных представителей на обработку ПДн и публикацию.
3. **Финансовая прозрачность**:
   - 20% комиссия преподавателям исключительно с фактически подтвержденных оплат.
   - Идемпотентность webhook'ов и финансовых транзакций (защита от двойных начислений).
   - Двусторонняя бухгалтерская модель журнала операций (Ledger).
4. **Абстракция платежей**:
   - Единый интерфейс провайдера (`PaymentGateway`), поддержка Mock-провайдера для локальной разработки и тестов, готовность к подключению CloudPayments/ЮKassa/Stripe.
5. **Двуязычность (RU / EN)**:
   - Полная синхронная локализация публичной части, форм, статусов, ошибок и дипломов.

## 3. Фазы разработки (Production Milestones)

### Этап A — Параллельная аналитика (В процессе)
- `researcher` (Product Architect): `PRODUCT_REQUIREMENTS.md`, `USER_FLOWS.md`, `OPEN_QUESTIONS.md`, `ARCHITECTURE.md`.
- `ui-ux-designer` (UI/UX Lead): `DESIGN_SYSTEM.md`, `PAGE_MAP.md`, `COMPONENTS.md`, `RESPONSIVE.md`.
- `Director`: аудит, git init, стек, план, извлечение Refero спецификаций.

### Этап B — Утверждение архитектуры и контрактов
- Утверждение технологического стека (`docs/TECH_STACK.md`).
- Утверждение контрактов API (`docs/API_CONTRACTS.md`) и схемы базы данных.
- Разделение зон ответственности перед параллельной разработкой.

### Этап C — Параллельная разработка (Backend & Frontend)
- **Backend Specialist**:
  - Модели данных, реляционная схема БД (SQLite/Prisma/Drizzle), миграции.
  - JWT / Session Auth, ролевой контроль доступа (Participant, Teacher, Jury, Admin).
  - Управление заявками (Draft -> Submitted -> Payment Pending -> Paid -> Under Review -> Evaluated -> Completed).
  - Реферальная система: генерация кодов, трекинг источника, начисление 20%, баланс преподавателя.
  - Оценивание: критерии, баллы, черновики, аудит-лог оценок.
  - Генерация дипломов (PDF).
  - Идемпотентный Mock Payment Webhook.
- **Frontend Specialist**:
  - Изоляция стилей: Public (Art Gallery) vs Dashboards (Cinema Frame.io).
  - Публичные страницы: Главная (espressivo VOCAL), Конкурсы, Номинации, Правила, Жюри, О нас, Вход, Регистрация.
  - Личный кабинет Участника (Заявка, Видео, Статусы, Диплом).
  - Личный кабинет Преподавателя (Рефералы, 20% комиссия, Финансы, Выплаты).
  - Личный кабинет Жюри (Оценивание, Видеоплеер, Критерии).
  - Админ-панель (Конкурсы, Заявки, Жюри, Финансы, Дипломы, Настройки).
  - Локализация RU/EN switcher.

### Этап D — Интеграция и сборка
- Подключение фронтенда к реальному API.
- Проверка end-to-end потоков.
- Устранение дефектов интеграции.

### Этап E — QA & Безопасность
- `qa-engineer`: аудит доступа, защита ссылок на видео, проверка идемпотентности оплат, регрессионное тестирование всех сценариев.
- Формирование `docs/QA_REPORT.md` и `docs/SECURITY_REPORT.md`.

### Этап F — Финализация, Документация и Сдача
- `README.md`, `.env.example`, руководство запуска, Swagger / OpenAPI specs.
- Проверка чистоты репозитория, коммитов, отсутствие уязвимостей и секретов.
