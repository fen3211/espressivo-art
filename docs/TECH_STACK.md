# espressivo ART — Technology Stack & Architectural Decision Record (ADR)

## 1. Стек технологий

| Слой | Выбранная технология | Обоснование выбора |
| :--- | :--- | :--- |
| **Язык** | **TypeScript 5.x** (Strict Mode) | Сквозная типизация доменных сущностей (заявка, оценка, транзакция), предотвращение ошибок рантайма, строгий запрет на `any`. |
| **Фреймворк** | **Next.js 15 (App Router) + React 19** | Единая экосистема для SSR (критично для публичной арт-галереи и SEO) и надежных серверных API Route Handlers. Одинаково быстро разворачивается локально одной командой `npm run dev`. |
| **База данных** | **SQLite (WAL mode)** via **Prisma ORM** | - Автономность: не требует установки внешних СУБД (Postgres/MySQL) для локального запуска заказчиком.<br>- ACID транзакции: критично для финансового журнала и начисления реферальной комиссии.<br>- Бесшовный перенос: в production достаточно изменить одну строчку в `schema.prisma` (`provider = "postgresql"`). |
| **Стилизация и изоляция** | **Tailwind CSS + Scoped Data Attributes (`data-theme`)** | Строгая изоляция двух стилей без взаимного загрязнения:<br>- `[data-theme="art"]`: монохром, 0px radius, Adobe/EB Garamond, костяная бумага `#e7e7e7`.<br>- `[data-theme="cinema"]`: темный космос `#0a0a13`, Iris Glow `#6199f6`, 10px radius, 100px pill buttons. |
| **Аутентификация & RBAC** | **HTTP-Only Cookie Sessions (JWT via `jose` / `bcryptjs`)** | Полная независимость от платных сторонних SaaS (Clerk, Auth0). Безопасные HttpOnly / SameSite cookies, хэширование паролей с солью, серверная проверка ролей `PARTICIPANT`, `TEACHER`, `JURY`, `ADMIN`. |
| **Генерация дипломов** | **PDFKit / Canvas PDF Engine** | Генерация векторных типографических PDF-дипломов высокой печати в эстетике Art+Commerce без тяжелых браузерных движков (Puppeteer), мгновенная отдача через Stream API. |
| **Платежный шлюз** | **Паттерн Gateway (`PaymentProviderInterface`)** | Абстракция провайдера с реализацией `MockPaymentGateway` (генерация платежной ссылки, проверка подписи, идемпотентная обработка вебхуков) и готовыми интерфейсами для CloudPayments / ЮKassa. |
| **Локализация (i18n)** | **Собственная типобезопасная система словарей (RU / EN)** | Отсутствие тяжелых внешних зависимостей, нулевой оверхед, переключение языков на лету, типизированные ключи переводов для фронтенда и бэкенда. |
| **Тестирование** | **Vitest + Node Test Runner** | Мгновенный запуск тестов без лишнего транспиляционного оверхеда, поддержка TypeScript из коробки. |

## 2. Архитектурные ограничения и безопасность
1. **Защита несовершеннолетних**: Ссылки на конкурсные видео и персональные данные ребенка не отдаются публично. Жюри получает заявку в обезличенном виде (Code/ID, номинация, категория, видеоматериал).
2. **Идемпотентность платежей**: Каждое платежное событие (`event_id` / `payment_id`) проверяется по уникальному индексу в таблице `PaymentTransactions`. Повторный вебхук отклоняется со статусом 200 OK без повторного начисления комиссии.
3. **Финансовый журнал (Ledger)**: Баланс преподавателя рассчитывается исключительно на основании записей журнала транзакций со статусом `CONFIRMED`. Прямое редактирование баланса в базе данных запрещено.
