# espressivo ART — International Creative Competition Platform

Полнофункциональный MVP международной конкурсной платформы **espressivo ART** с флагманским творческим конкурсом вокального искусства для детей и молодёжи **«espressivo VOCAL — Young Talents»**.

Архитектура платформы спроектирована и реализована командой специализированных AI-инженеров под руководством главного AI Development Director в строгом соответствии с техническим заданием и двумя независимыми дизайн-системами Refero.

## 2. Реализованный функционал платформы

### 2.1. Публичный портал
- **Главная монография**: Интерактивный лонгрид первого конкурса *espressivo VOCAL — Young Talents*.
- **Разделы**:
  - `/competitions`: Каталог сезонов (Вокал, Фортепиано, Струнные) с фильтрацией.
  - `/competitions/:slug`: Страница конкурса с таймлайном этапов, тарифами и реферальной программой.
  - `/competitions/:slug/nominations`: Сетка 4 номинаций (Академический, Эстрадный, Народный вокал, Хоровое пение) и 4 возрастных категорий.
  - `/competitions/:slug/rules`: Официальный регламент с требованиями к немонтированному видео и критериями.
  - `/jury`: Галерея международного жюри (Вена, Милан, Париж, Санкт-Петербург, Лондон).
  - `/about`: Институциональный манифест культурного фонда.
  - `/login`: Форма входа с авторедиректом и кнопками демонстрационного быстрого входа в 1 клик для всех 4 ролей.
  - `/register`: Регистрация с выбором роли (Участник / Преподаватель) и автоподхватом `?ref=` промокода из URL.
- **Двуязычие**: Мгновенное переключение RU / EN на всех экранах (`LanguageContext`).

### 2.2. Кабинет Участника (`/dashboard/**`)
- Сводка заявок, актуальные статусы жизненного цикла (`DRAFT` → `SUBMITTED` → `PAYMENT_PENDING` → `PAID` → `UNDER_REVIEW` → `EVALUATED` → `COMPLETED`).
- 5-шаговый мастер подачи заявки: данные ребенка, выбор номинации и возрастной группы, прикрепление видеоматериалов с превью, согласия родителей (152-ФЗ / публикация).
- Сохранение черновиков и редактирование до отправки на оплату.
- Просмотр оценок коллегии жюри и рецензий экспертов.
- Галерея наград и скачивание официального полиграфического диплома в формате PDF.

### 2.3. Кабинет Преподавателя (`/teacher/**`)
- **Реферальная программа**: Персональный реферальный код и реферальная ссылка с кнопкой быстрого копирования и QR-кодом.
- **Автоматическое начисление 20%**: Комиссия начисляется исключительно с фактически подтвержденных оплат привлеченных участников.
- **Финансовый реестр (Ledger)**: Двойная бухгалтерия проводок, доступный баланс.
- **Заявки на выплату**: Форма вывода средств на банковские реквизиты/карту с валидацией баланса, проверкой минимальной суммы (1000 ₽) и защитой от параллельного овердрафта.

### 2.4. Кабинет Жюри (`/jury/**`)
- Очередь назначенных заявок с прогрессом оценивания.
- **Режим «Слепое прослушивание» (Blind Audition)**: Полное исключение персональных данных ребенка, родителей, школы и педагога на уровне API (`JuryApplicationProjectionDTO`).
- **Кинематографичный видеотерминал**: Плеер с водяным знаком, 4 независимых слайдера критериев по 25 баллов (Техника, Музыкальность, Артистизм, Сложность репертуара = 100 баллов max), расчет лауреатской степени в реальном времени, текстовая рецензия.
- **Защита от изменений**: Автосохранение черновика и блокировка протокола после финальной сдачи (403 Forbidden).

### 2.5. Административная панель (`/admin/**`)
- Командный центр: KPI выручки, количество заявок, обязательства перед педагогами, статус шлюза.
- Управление пользователями и назначение ролей (Participant, Teacher, Jury, Admin).
- Управление конкурсами, номинациями и возрастными категориями без изменения исходного кода.
- Модерация конкурсных видеоматериалов и матрица назначения экспертов жюри на заявки.
- Автоматический подсчет результатов, нормализация оценок и пакетная генерация лауреатских степеней.
- Бухгалтерский журнал эквайринга и одобрение заявок на выплату преподавателям.

### 2.6. Векторные дипломы высокой печати (PDF)
- Генерация сертификатов через движок `pdfkit` в строгой эстетике Art+Commerce.
- Уникальный регистрационный номер, ФИО лауреата, степень, подписи председателя жюри.
- Криптографический токен и публичная ссылка онлайн-валидации подлинности диплома по QR-коду (`/api/public/verify-certificate/:token`).

### 2.7. Платежный шлюз и защита финансов
- Паттерн `PaymentGatewayInterface` с реализацией `MockPaymentGateway`.
- Криптографическая валидация подписи HMAC-SHA256.
- **Идемпотентность**: Гарантия однократной обработки вебхука (`ALREADY_PROCESSED`), исключающая повторное начисление комиссии преподавателю.
- Защита от race conditions при списании баланса.

## 4. Быстрый старт и локальный запуск

### 4.1. Предварительные требования
- Node.js 18.18+ (рекомендуется Node.js 20+ или 24)
- npm 9+

### 4.2. Установка и запуск

1. Перейдите в каталог проекта:
   ```bash
   cd d:\Projects\espressivo-art
   ```

2. Установите зависимости:
   ```bash
   npm install
   ```

3. Инициализируйте базу данных и сгенерируйте Prisma Client:
   ```bash
   npx prisma db push
   ```

4. Заполните базу данных демонстрационными данными (пользователи всех 4 ролей, конкурсы, заявки, оценки, дипломы):
   ```bash
   node prisma/seed.js
   ```

5. Запустите сервер разработки:
   ```bash
   npm run dev
   ```
   Платформа откроется по адресу: **http://localhost:3000**

В базе данных преднастроены пользователи для всех 4 ролей (пароль для всех: `pass1234`):

| Роль | Email | Пароль | Описание и возможности |
| :--- | :--- | :--- | :--- |
| **Участник** | `participant@espressivo.art` | `pass1234` | Подача заявки, привязка видео, просмотр статуса и оценок, скачивание диплома |
| **Преподаватель** | `teacher@espressivo.art` | `pass1234` | Реферальный код `TEACHER-MARIA`, баланс 12 500 ₽, учет 20% комиссии, заявки на вывод |
| **Член жюри** | `jury@espressivo.art` | `pass1234` | Очередь заявок, слепое оценивание (Blind Audition), видеотерминал с 4 слайдерами |
| **Администратор** | `admin@espressivo.art` | `pass1234` | Управление платформой, модерация, назначение жюри, подсчет лауреатов, аудит финансов |

> **Защита безопасности в production**:
> - Кнопки быстрого входа в 1 клик на `/login` отображаются **только в development/staging** окружениях (`NODE_ENV !== 'production'`).
> - В production вход под демонстрационными email **безусловно заблокирован** на уровне API без возможности отмены через переменные окружения. Ответ унифицирован (`401 INVALID_CREDENTIALS`, constant-time bcrypt), что предотвращает утечку существования аккаунтов.
> - Все эндпоинты авторизации защищены распределённым `RateLimiter` (`lib/rate-limiter.ts`) с поддержкой Upstash/Redis, защитой от спуфинга `X-Forwarded-For` и политикой **Fail-Closed** (HTTP 503) при отсутствии хранилища в production.
> - Члены жюри аппаратно ограничены режимом **Blind Audition**: сервер возвращает `videoUrl: null`, в DOM монтируется исключительно аудиоэлемент, переключение режима в UI заблокировано.
> - Публичная верификация дипломов строго изолирует ПДн несовершеннолетних (ст. 10.1 152-ФЗ): имя и баллы не раскрываются без отдельного согласия законного представителя.
> - Seed-скрипт базы данных `prisma/seed.js` блокирует запуск в production без флага `ALLOW_PROD_SEED="true"`.

## 8. Статус готовности платформы (Staging Ready / MVP)

> **Критерий Production Readiness**:  
> В соответствии с инженерными стандартами платформы, продукт имеет подтверждённый статус **Staging Ready / MVP** (полная функциональная готовность к сквозному приёмочному тестированию).  
> Продукт **не** маркируется как Production Ready до выполнения трёх внешних организационных условий:
> 1. Заключение официального договора с платёжным агрегатором (ЮKassa / CloudPayments) и замена mock-шлюза на сертифицированный боевой драйвер.
> 2. Заключение внешней квалифицированной юридической экспертизы по документам из каталога `docs/legal/`.
> 3. Подключение внешнего транзакционного провайдера email/SMS (Resend / UniSender) и постоянного объектного хранилища S3.

### 8.1. Полностью проверенные и верифицированные функции (Verified MVP Features)
- **Безопасность авторизации**: Сессионная аутентификация на HttpOnly cookies с криптостойким JWT (HS256 via `jose`), принудительный запрет дефолтных секретов, rate-limiting попыток входа (429), блокировка демо-аккаунтов в production.
- **Двухмировая изоляция стилей**: Строгое разделение тем `theme-art` (Quiet Editorial Gallery) и `theme-cinema` (Midnight Projection Room) без визуального конфликта.
- **Подача заявок и защита несовершеннолетних (152-ФЗ / GDPR)**: Раздельное получение согласий (обязательное согласие на ПДн и опциональное на публикацию), динамическая генерация шифров заявок (`EXP-${year}-${code}`), строгая серверная валидация возраста и номинаций.
- **Терминал жюри и слепое судейство (Blind Audition)**: Полное исключение персональных данных участника, родителей, педагога и школы на уровне API; неотключаемый режим blind audition с непрозрачной шторкой для сохранения аудиодорожки; 100-балльное судейство по 4 критериям; фиксация протоколов с запретом правок (403 Forbidden).
- **Партнерская программа и финансовый учет**: Автоматическое начисление 20% комиссии наставникам исключительно по подтвержденным оплатам, двойная запись в ledger, атомарные транзакции с защитой от race conditions, валидация лимита выплат (от 1 000 ₽) с предотвращением овердрафта.
- **Векторные дипломы высокой печати (PDF)**: Встроенные открытые шрифты SIL OFL Noto Serif (гарантия рендеринга кириллицы в Docker/Linux без системных шрифтов Windows), внедрение высокоточного QR-кода верификации, 256-битный энтропийный токен.
- **Публичная верификация подлинности**: Защищённый эндпоинт `/verify/[token]` с маскированием ФИО несовершеннолетних (`Имя Ф.`) и нулевой утечкой персональных контактов.
- **Двуязычность (RU / EN)**: 100% синхронизация словарей (13 разделов, 520+ ключей), полное отсутствие кириллицы в английской локали, поддержка двуязычия на страницах оплаты и верификации.

### 8.2. Демонстрационные механизмы (Staging Mock Implementations)
- **Mock Payment Gateway**: Эмуляция полного платежного цикла (генерация ссылки, HMAC-подпись вебхука, проверка идемпотентности).  
  *Критические барьеры безопасности*: Требуется криптостойкий секрет `MOCK_PAYMENT_SECRET` (>= 32 символов); запуск mock checkout в `production` полностью заблокирован, если не задан специальный флаг `ENABLE_MOCK_CHECKOUT="true"`; страница оплаты требует обязательной авторизации и проверяет принадлежность заявки текущему пользователю; запрещен вызов по чистому `appId`.
